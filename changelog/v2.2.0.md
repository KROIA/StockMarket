## Security

| Tag | Change |
|---:|---|
| ![hardening] | The number of price-history candles a client may request is limited to the server cap |
| ![hardening] | `IAsyncMarket.putOrderAsync()` on a slave server gets the same checks as a player order: the master places the order only for a member of the bank account with the trade permissions and enough balance, reserves the money or items, and applies the max order size and trade cooldown. Bot orders and orders for another market are refused |
| ![hardening] | A modified client can no longer create or delete markets without StockMarket admin mode, or read or change another player's preferences, through the market manager request |
| ![hardening] | An untrusted slave server can no longer read a player's active orders, order history, live order feed, preferences or admin mode, or any market's settings, by naming a player. | ![hardening] | The Mod Settings screen again requires operator level 2 in addition to StockMarket admin mode, and only works on the master server. The server checks both for every read and change of the mod settings, and the Mod Settings button is hidden for players who don't meet them |

## Order Limits

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Max order size per market</summary>New "Max order size" field in the Market Settings and in the presets: the most items a single player order may buy or sell on that market; 0 = unlimited. The default is `max(factor, factor x abundance)` with the new Mod Setting "Max order size factor" (`MAX_ORDER_VOLUME_FACTOR`, default 64: abundance 5 = 320, 30 = 1,920, 200 = 12,800), used for new markets, presets and saves without a value. Changing the factor keeps existing limits; its "Apply to all markets" button (with confirmation) recomputes every market's max order size from its abundance and the saved factor, overwriting custom limits. The trade screen respects the limit: the amount box and the +X buttons never go above it and a larger typed amount snaps down to it; a rejected order tells the player the max size. Bots are not limited</details> |
| ![feature] | <details><summary>Trade cooldown against autoclicker spam</summary>New Mod Setting "Trade cooldown (ms)" (`TRADE_COOLDOWN_MS`, default 500 ms, 0 = off): minimum time between two accepted orders of the same player, shared across all markets and pair orders. While it runs, the Buy and Sell buttons get a light gray overlay and ignore clicks; an order placed too fast is rejected with the remaining wait time. Rejected orders do not restart the cooldown; bots are not affected</details> |
| ![feature] | <details><summary>The virtual order book remembers consumed depth after large price moves</summary>Virtual volume consumed outside the visible order book window stays thin, so a price that returns meets little volume. The book remembers the actual remaining volume per 2% price band, from price 1 up to the ask ceiling, and lets it recover toward the default over time. The default is only the recovery target: a price move no longer makes the depth far outside the window jump to the default at the new price, and new price bands above an earlier ceiling start empty and recover. New Mod Setting "Virtual depth recovery half-life (min)" (`MARKET.VIRTUAL_DEPTH_RECOVERY_HALF_LIFE_MINUTES`, default 30, 0 = off): the difference to the default halves after this time</details> |
| ![feature] | <details><summary>Trend accumulation in the virtual order book</summary>The volume distribution plugin tracks a moving average of the price. While the price is above it, sell-side depth refills faster and buy-side depth slower (below it the other way round), both inside the order book window and in the remembered depth outside it, so the book leans against a sustained move. Three new volume distribution plugin settings: "Trend Period (min)" (moving average time constant, default 10), "Trend Gain" (default 10, 0 = off) and "Trend Max Factor" (largest speed-up or slow-down, default 4, 1 = off)</details> |
| ![feature] | <details><summary>Volume clusters at round prices in the virtual order book</summary>The default book adds extra volume around round prices (10, 20, 25, 30, 50, 100, 200, ...), strongest near the market's fair price but still visible far away (on a market at 160 the sell cluster at 1,000 adds about a fifth of the near-price depth on top of the plain book). Three new volume distribution plugin settings: "Round Level Scale" (default 1, 0 = off), "Round Level Width" (default 0.03) and "Round Level Range" (default 1.1)</details> |
| ![breaking] | <details><summary>Virtual order book depth is the same per percent of price on every market</summary>The default book now holds the same depth per percent of price on every market, sized to a reference order of max(64, 64 x abundance) items: with Volume Scale 1, one reference order moves the price about 0.36 % whatever the item costs (diamond keeps its current depth). Expensive items get a much thinner book than before (at least 0.1 items per price step) and move more; cheap items such as dirt get a much deeper book and move less per item, but still in whole price steps. The market's max order size does not affect the depth; stored Volume Scale values are kept. The book is centred on the market's fair price (the NetFlowPlugin equilibrium, else the default price) instead of the last traded price; buy volume sits below the current price and sell volume above it, so a dump or pump no longer drags the book along and buying back after a crash meets the depth the crash sold into. Sell interest grows the further a price level is above the fair price (the mirror of the buy-side demand boost, about a third of the near-price depth per price step at 6 times the fair price), so the sell side never runs dry. Every existing book is rebuilt once on the first load, and again whenever a market's default price changes</details> |
| ![feature] | <details><summary>Price ceiling for virtual sell volume</summary>No virtual sell volume exists above a multiple of the current price. New Mod Setting "Virtual depth price ceiling (x price)" (`MARKET.VIRTUAL_DEPTH_MAX_PRICE_MULTIPLIER`, default 100x, range 2 - 10000): a buy that walks the book stops there and its remainder is cancelled</details> |
| ![improvement] | Default market presets: abundance ×10, giving a 10× deeper default order book and a 10× higher default max order size. Only applies to newly generated preset files and new markets; existing `config/StockMarket/market_presets` files and markets keep their values |
| ![improvement] | Markets without a preset, created by command or via the API default to abundance 100 (max order 6400, bot cap 64000) |
| ![breaking] | <details><summary>Existing markets get a max order size on first load</summary>Markets from older saves and older preset files receive the derived default (one stack per abundance point, at least 64) on the first load after updating. Bulk orders above it are rejected until an admin raises the limit or sets it to 0. Moving an existing order on the chart is never blocked by the limit or the cooldown</details> |
| ![breaking] | **Compatibility:** the market settings and preset network format changed. Clients, servers and all master/slave servers must run the same StockMarket version |

## Bug Fixes

| Tag | Change |
|---:|---|
| ![bugfix] | `/stockmarket op` and `deop` could change the wrong StockMarket user when two users had the same name, for example after a server switched online mode on or off. They reported success, but the player stayed without admin mode. Without a name they now always change the executing player. With a name they prefer the player who is online. When a player joins with a name an older stored user still holds, the older user's name gets an "(old ...)" suffix; its data stays as it is. If several stored users still share a name, the command refuses and says so |
