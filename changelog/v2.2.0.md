## Security

| Tag | Change |
|---:|---|
| ![hardening] | The number of price-history candles a client may request is limited to the server cap |

## Performance

| Tag | Change |
|---:|---|
| ![improvement] | Chart history loads instantly: the server reads only the requested page of candles (512 by default) instead of the full market history, and older pages are fetched by candle count so they cross downtime gaps. On a server with ~115k candles per market the first 1m chart load dropped from ~2.5 s to ~33 ms and the payload from 65 KB to 8 KB |

## Placeholders

| Tag | Change |
|---:|---|
| ![feature] | TAB and Placeholder API placeholders through the ModUtilities placeholder registry: price, 24h change and 24h volume per trading pair, player open orders and portfolio value, each with a `_raw` variant; slave servers pull the values from the master. See the [placeholder guide](../documentation/user-guide/placeholders.md) |

## API

| Tag | Change |
|---:|---|
| ![breaking] | <details><summary>Exploit-prevention open/close renamed to maintenance mode on the market API</summary>`ISyncServerMarket.isMarketOpen()/setMarketOpen()` are now `isUnderMaintenance()/setMaintenance()`, `IAsyncMarket.isMarketOpenAsync()/setMarketOpenAsync()` are now `isUnderMaintenanceAsync()/setMaintenanceAsync()`. `IStockMarketIntegration.setMarketOpen/isMarketOpen` keep their names.</details> |
| ![breaking] | `IPluginMarket.isMarketOpen()` now returns true only if the market is not under maintenance **and** inside its trading hours |
| ![feature] | Trading-hours API: `isTradingOpen()`, `getTradingState()`, `setTradingHours(open, close)`, `setTradingOverride(open)` on `ISyncServerMarket` and async variants on `IAsyncMarket` |
| ![feature] | New `CreateOrderRequest.Status.MARKET_CLOSED` for orders rejected outside trading hours |

## Trading Hours

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Per-market trading hours</summary>Each market has an open and close time (HH:MM, default 00:00-24:00 = always open, overnight windows allowed). A global Mod Setting chooses between in-game time and the server's real time. A closed market is frozen: no new orders from players, bots, plugins or inter-market trades, pending orders are kept and can still be cancelled, candles stay flat and plugins skip the market. Inter-market orders require both markets to be open. See the [trading hours guide](../documentation/user-guide/trading-hours.md)</details> |
| ![feature] | `/stockmarket open <market>` and `/stockmarket close <market>` override the schedule until the next scheduled transition; market suggestions show the numeric ID with the item name as tooltip |
| ![feature] | Trading panel shows the market's trading hours, a clock and a "Market Closed" / "Under Maintenance" banner |
| ![feature] | Market settings: trading hours row with "Apply to all" (with confirmation) and the current server time |

## Maintenance Mode

| Tag | Change |
|---:|---|
| ![improvement] | The former market open/close (exploit prevention) toggle is now called "Maintenance mode" in the GUI, lang files and docs, with a tooltip explaining it |
| ![improvement] | Maintenance state is now saved and survives a server restart |
| ![bugfix] | Enabling maintenance through the market settings now cancels player orders, the same as the checkbox |

## Villager Trading

| Tag | Change |
|---:|---|
| ![improvement] | Villager trade data is now stored in the StockMarket data folder (`data/StockMarket/villager_trades.nbt`) instead of vanilla world storage, on master and slave servers; existing worlds are migrated automatically on server start |
| ![improvement] | Slave servers now also save their villager trade data on the autosave interval instead of only at server stop, so a crash loses at most one interval of villager trades |

## Bug Fixes

| Tag | Change |
|---:|---|
| ![bugfix] | Server tick handlers were not removed on server stop and stacked up after switching singleplayer worlds; the same applied to the BankSystem event listeners (villager trade broadcast, trust sync, ItemID merge) |
| ![bugfix] | JEI integration was never loaded on Fabric because the mod did not register its JEI plugin entrypoint; the plugin also used the BankSystem plugin id instead of its own |
| ![bugfix] | Stopping the server closed the price/order database while queued writes (such as the final price candle save) were still pending, which could lose them; the database now finishes all queued writes first, and writes arriving after shutdown are rejected with an error log instead of failing silently |
| ![bugfix] | An order rejected on a market under maintenance was reported as created |
| ![bugfix] | Moving an order on the chart of a closed market could lose the order; it is now refused |
| ![bugfix] | TargetPriceBot no longer makes a price jump after a long market closure (PID time step clamped) |
| ![bugfix] | Trade screen (pair mode) and display block chart leaked market price-stream subscriptions |
| ![hardening] | The display block price chart is registered in the ModUtilities GUI element registry, so a display GUI rebuilt on the client from a server structure update keeps its chart instead of dropping it |
