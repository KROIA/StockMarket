## Performance

| Tag | Change |
|---:|---|
| ![improvement] | Chart history loads instantly: the server reads only the requested page of candles (512 by default) instead of the full market history, and older pages are fetched by candle count so they cross downtime gaps. On a server with ~115k candles per market the first 1m chart load dropped from ~2.5 s to ~33 ms and the payload from 65 KB to 8 KB |
| ![improvement] | Large market buys and sells no longer scan every empty price level outside the order book window: the matching walk jumps over whole price slots whose remembered depth is below one item per level. A buy into empty depth at price 160 now ends in under 1 ms instead of ~115 ms; fills are unchanged |

## Order Limits

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Max order size per market</summary>New "Max order size" field in the Market Settings and in the presets: the most items a single player order may buy or sell on that market. The default is one stack per abundance point, at least 64 (abundance 5 = 320, 30 = 1,920, 200 = 12,800); 0 = unlimited. Bots are not limited</details> |
| ![feature] | <details><summary>Trade cooldown against autoclicker spam</summary>New Mod Setting "Trade cooldown (ms)" (`TRADE_COOLDOWN_MS`, default 500 ms, 0 = off): minimum time between two accepted orders of the same player, shared across all markets and pair orders. Rejected orders do not restart the cooldown; bots are not affected</details> |
| ![feature] | Players get a clear message when an order is too large (with the max size) or placed too fast (with the remaining wait time) |
| ![feature] | <details><summary>Mod Setting "Max order size factor" with "Apply to all markets"</summary>New Mod Setting `MAX_ORDER_VOLUME_FACTOR` (default 64): the items per abundance point used for the default max order size, `max(factor, factor x abundance)`, for new markets, presets and saves without a value. Existing markets keep their limit; the "Apply to all markets" button (with confirmation) recomputes every market's max order size from its abundance and the saved factor, overwriting custom limits</details> |
| ![feature] | <details><summary>The virtual order book remembers consumed depth after large price moves</summary>Virtual volume consumed outside the visible order book window stays thin, so a price that returns meets little volume. The book remembers the actual remaining volume per 2% price band, from price 1 up to the ask ceiling, and lets it recover toward the default over time. The default is only the recovery target: a price move no longer makes the depth far outside the window jump to the default at the new price, and new price bands above an earlier ceiling start empty and recover. New Mod Setting "Virtual depth recovery half-life (min)" (`MARKET.VIRTUAL_DEPTH_RECOVERY_HALF_LIFE_MINUTES`, default 30, 0 = off): the difference to the default halves after this time</details> |
| ![feature] | <details><summary>Trend accumulation in the virtual order book</summary>The volume distribution plugin tracks a moving average of the price. While the price is above it, sell-side depth refills faster and buy-side depth slower (below it the other way round), both inside the order book window and in the remembered depth outside it, so the book leans against a sustained move. Three new volume distribution plugin settings: "Trend Period (min)" (moving average time constant, default 10), "Trend Gain" (default 10, 0 = off) and "Trend Max Factor" (largest speed-up or slow-down, default 4, 1 = off)</details> |
| ![feature] | <details><summary>Volume clusters at round prices in the virtual order book</summary>The default book adds extra volume around round prices (10, 20, 25, 30, 50, 100, 200, ...), strongest near the current price but still visible far away (on a market at 160 the sell cluster at 1,000 holds about a fifth of the near-price depth). Three new volume distribution plugin settings: "Round Level Scale" (default 1, 0 = off), "Round Level Width" (default 0.03) and "Round Level Range" (default 1.1)</details> |
| ![breaking] | <details><summary>Virtual order book depth is the same per percent of price on every market</summary>The default book now holds the same depth per percent of price on every market, sized to a reference order of max(64, 64 x abundance) items: with Volume Scale 1, one reference order moves the price about 0.36 % whatever the item costs (diamond keeps its current depth). Expensive items get a much thinner book than before (at least 0.1 items per price step) and move more; cheap items such as dirt get a much deeper book and move less per item, but still in whole price steps. The market's max order size does not affect the depth; stored Volume Scale values are kept. Every existing book is rebuilt once on the first load, and again whenever a market's default price changes</details> |
| ![feature] | <details><summary>Price ceiling for virtual sell volume</summary>No virtual sell volume exists above a multiple of the current price. New Mod Setting "Virtual depth price ceiling (x price)" (`MARKET.VIRTUAL_DEPTH_MAX_PRICE_MULTIPLIER`, default 100x, range 2 - 10000): a buy that walks the book stops there and its remainder is cancelled</details> |
| ![improvement] | Default market presets: abundance ×10, giving a 10× deeper default order book and a 10× higher default max order size. Only applies to newly generated preset files and new markets; existing `config/StockMarket/market_presets` files and markets keep their values |
| ![improvement] | Markets without a preset, created by command or via the API default to abundance 100 (max order 6400, bot cap 64000) |
| ![improvement] | The trade screen respects the market's max order size: the amount box and the +X buttons never go above it, and a larger typed amount snaps down to the limit |
| ![improvement] | The Buy and Sell buttons get a light gray overlay and ignore clicks while the trade cooldown runs, until the next order is allowed |
| ![breaking] | <details><summary>Existing markets get a max order size on first load</summary>Markets from older saves and older preset files receive the derived default (one stack per abundance point, at least 64) on the first load after updating. Bulk orders above it are rejected until an admin raises the limit or sets it to 0. Moving an existing order on the chart is never blocked by the limit or the cooldown</details> |
| ![breaking] | **Compatibility:** the market settings and preset network format changed. Clients, servers and all master/slave servers must run the same StockMarket version |

| Tag | Change |
|---:|---|
| ![breaking] | **Compatibility:** the plugin settings network format changed. Clients, servers and all master/slave servers must run the same StockMarket version, otherwise plugin settings cannot be exchanged |
| ![feature] | <details><summary>"Apply to all" button on every plugin settings screen</summary>Volatility, Target Price Bot, Orderbook Volume Distribution and News settings can be applied to every market subscribed to the plugin at once. A confirmation dialog shows how many markets will be overwritten; the previous per-market settings are lost</details> |
| ![feature] | Target Price Bot setting "Max Order Size Factor" (default 10, 0 = no bot limit): the largest bot order as a multiple of the market's max order size; editable per market in the plugin settings, older saves load with 10 |
| ![feature] | <details><summary>Faded net flow</summary>Each market keeps a decaying copy of the player net flow (Mod Setting `NET_FLOW_HALF_LIFE_MINUTES`, default 6 h (360 min) half-life, 0 = off). The Volatility plugin's equilibrium price uses it, so rapid buy/sell bursts fade out instead of pinning the price target. The Market Settings screen shows both the real and the faded net flow</details> |
| ![improvement] | Net flow half-life default raised from 10 min to 6 h (360 min): a trade keeps its effect on the equilibrium price for hours instead of fading within minutes. Worlds that still use the old default 10 are switched to 360 once on load; any other value, and a 10 set again later, is kept |
| ![feature] | <details><summary>Volatility plugin setting "Permanent impact" (default 0.5)</summary>Big trades still spike the price, but the lasting price shift is now at most half of the trade's own impact on the order book: the equilibrium never moves more than this fraction of the price move the same amount makes when it walks the default order book in one go. Pump strategies therefore lose against the reversion. "Flow sensitivity" stays as a lower limit. Markets without a volume distribution plugin keep the old behaviour (a warning is logged). Older saves load with 0.5. Expect steady player demand to move the price much more slowly than before (on diamond roughly +2% after 10 min, +13% after 1 h of sustained buying)</details> |
| ![feature] | Target Price Bot setting "Max target move per second" (default 0.5%/s): the bot's target follows the equilibrium price at a limited speed |
| ![feature] | <details><summary>Prices now drift back after a big trade instead of snapping back</summary>When a player pushes the price, the Target Price Bot holds it near that level and lets it return to its target over about 10 minutes, swinging around its way back like a real market. The bot never pushes the price past its target nor beyond the price the player reached. New Target Price Bot settings: "Reversion time" (default 600 s, 0 = off: old behaviour), "Oscillation period" (60 s), "Oscillation damping" (0.3) and "Oscillation amplitude" (0.15). Older saves load with these defaults</details> |
| ![improvement] | Target Price Bot reacts to the price gap in percent, so cheap items are steered toward their target price as firmly as expensive ones (an item at price 1 now settles about a third faster) |
| ![bugfix] | Target Price Bot no longer freezes on very cheap items (e.g. dirt at 0.10): it now moves their price toward the target again. When the target is less than one price step (0.01) away, the bot waits instead of jumping past it |
| ![bugfix] | The Target Price Bot waits at most 60 s after a player trade for the order book to refill before it trades again, so steady player buying can no longer keep it idle indefinitely |
| ![feature] | "Defaults" button in the Volatility, Target Price Bot and Volume Distribution plugin settings: fills the form with the plugin's default values; press Apply (this market) or Apply to all to reset |
| ![improvement] | Volatility "Scale" tooltip now states the realistic price swing (at 0.3: typically about ±4%, 90% of the time within ±12%, rarely up to about ±26%) instead of the misleading ±30% |
| ![improvement] | Tooltips on all plugin settings and on every Plugin Management control (enabled, auto-subscribe, logger, add, delete, move up/down, subscribe, market icons, open plugin screen) |
| ![improvement] | Plugin Management: clicking a plugin entry selects it (darker background) and the Left/Right arrow keys step through that plugin's subscribed markets for the chart, wrapping around; arrows are ignored while a text box has focus |
| ![feature] | The plugin page's order book volume display now marks the borders of the virtual order book's linear and log-scale ranges; hover a line to see which border it is |
| ![improvement] | Volatility plugin: once the price has reached its floor or ceiling, further one-sided flow no longer adds to the plugin's own price effect, so trading back moves the price immediately instead of first having to undo the excess flow. The market's net flow counter itself keeps counting every trade |
| ![improvement] | Volatility plugin defaults retuned against pump strategies (flow sensitivity 2000, max price multiplier 3×): steady player demand still moves the price, while buy-hold-sell pumps lose money. Existing markets keep their saved plugin settings; only new markets use the new defaults |
| ![feature] | <details><summary>New NetFlowPlugin: the player supply-and-demand price model is now its own plugin</summary>All net-flow settings moved from the Volatility plugin to the new NetFlowPlugin, which runs first and publishes the equilibrium price; the Volatility plugin now only adds its random walk on top. Each part of the model can be switched on or off per market: Player Flow Influence, Book Depth Cap (permanent impact limit) and Flow Saturation; the capacity's volatility divisor is its own setting (Capacity Volatility Scale, default 0.3). See the [NetFlowPlugin page](../documentation/user-guide/plugin-system/plugins/net-flow-plugin.md)</details> |
| ![feature] | <details><summary>Long-term anchor (NetFlowPlugin, off by default)</summary>When switched on per market, lasting one-sided trading slowly moves the price the flow is measured from, so part of a sustained trend stays after the flow has faded instead of the price always returning to the default price. Defaults: anchor time 2 days, at most 0.1 (about 10%) per day, between 0.25x and 4x the default price. Zero flow leaves the anchor where it is; Reset of the market's Net Flow also resets the anchor. The current anchor is shown read-only in the plugin settings</details> |
| ![improvement] | <details><summary>Existing worlds are migrated automatically</summary>On the first load a NetFlowPlugin is created in front of every Volatility plugin with the same subscriptions, auto-subscribe and enabled state, and each market's flow settings and saved flow state are copied over, so prices continue unchanged. Downgrading to an older version afterwards resets the Volatility plugin's flow settings to their defaults and logs an unknown-plugin warning for the NetFlowPlugin</details> |
| ![removal] | The plugin "Order" (subscription order) setting. Auto-subscribe of new markets now follows the plugin list (execution) order; saves that still contain the old value load normally and ignore it |

| ![feature] | <details><summary>Player trades are written to the BankSystem transaction ledger</summary>Every player order now has a persistent order ID (also stored in the order history, column `order_id`). The master writes `TRADE_BUY`/`TRADE_SELL` rows to the BankSystem ledger with the ref `sm:order:<id>` (inter-market orders: one row per leg, ref `sm:im:<group>`). Each row holds only the fills since the order's previous row: one row when an order closes, one every 10 minutes for resting orders whose fill state changed, and one on server stop for partly filled open orders. Bot orders write no rows. Orders from older saves get an ID on first use. With a BankSystem without the ledger API no rows are written and trading works as before</details> |
