## Performance

| Tag | Change |
|---:|---|
| ![improvement] | Chart history loads instantly: the server reads only the requested page of candles (512 by default) instead of the full market history, and older pages are fetched by candle count so they cross downtime gaps. On a server with ~115k candles per market the first 1m chart load dropped from ~2.5 s to ~33 ms and the payload from 65 KB to 8 KB |

| ![feature] | `IPluginMarket.setNetPlayerItemFlow(double)` overwrites a market's net player item flow counter; it is a default (no-op) method, so existing `IPluginMarket` implementations keep compiling |

## Trading Hours

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Per-market trading hours</summary>Each market has an open and close time (HH:MM, default 00:00-24:00 = always open, overnight windows allowed). A global Mod Setting chooses between in-game time and the server's real time. A closed market is frozen: no new orders from players, bots, plugins or inter-market trades, pending orders are kept and can still be cancelled, candles stay flat and plugins skip the market. Inter-market orders require both markets to be open. See the [trading hours guide](../documentation/user-guide/trading-hours.md)</details> |
| ![feature] | `/stockmarket open <market>` and `/stockmarket close <market>` override the schedule until the next scheduled transition; market suggestions show the numeric ID with the item name as tooltip |
| ![feature] | Trading panel shows the market's trading hours, a clock and a "Market Closed" / "Under Maintenance" banner |
| ![feature] | Market settings: trading hours row with "Apply to all" (with confirmation) and the current server time |

## Order Limits

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Max order size per market</summary>New "Max order size" field in the Market Settings and in the presets: the most items a single player order may buy or sell on that market. The default is one stack per abundance point, at least 64 (abundance 5 = 320, 30 = 1,920, 200 = 12,800); 0 = unlimited. Bots are not limited</details> |
| ![feature] | <details><summary>Trade cooldown against autoclicker spam</summary>New Mod Setting "Trade cooldown (ms)" (`TRADE_COOLDOWN_MS`, default 500 ms, 0 = off): minimum time between two accepted orders of the same player, shared across all markets and pair orders. Rejected orders do not restart the cooldown; bots are not affected</details> |
| ![feature] | Players get a clear message when an order is too large (with the max size) or placed too fast (with the remaining wait time) |
| ![feature] | <details><summary>Mod Setting "Max order size factor" with "Apply to all markets"</summary>New Mod Setting `MAX_ORDER_VOLUME_FACTOR` (default 64): the items per abundance point used for the default max order size, `max(factor, factor x abundance)`, for new markets, presets and saves without a value. Existing markets keep their limit; the "Apply to all markets" button (with confirmation) recomputes every market's max order size from its abundance and the saved factor, overwriting custom limits</details> |
| ![improvement] | Default market presets: abundance ×10, giving a 10× deeper default order book and a 10× higher default max order size. Only applies to newly generated preset files and new markets; existing `config/StockMarket/market_presets` files and markets keep their values |
| ![improvement] | The trade screen respects the market's max order size: the amount box and the +X buttons never go above it, and a larger typed amount snaps down to the limit |
| ![improvement] | The Buy and Sell buttons get a light gray overlay and ignore clicks while the trade cooldown runs, until the next order is allowed |
| ![breaking] | <details><summary>Existing markets get a max order size on first load</summary>Markets from older saves and older preset files receive the derived default (one stack per abundance point, at least 64) on the first load after updating. Bulk orders above it are rejected until an admin raises the limit or sets it to 0. Moving an existing order on the chart is never blocked by the limit or the cooldown</details> |
| ![breaking] | **Compatibility:** the market settings and preset network format changed. Clients, servers and all master/slave servers must run the same StockMarket version |

## Maintenance Mode

| Tag | Change |
|---:|---|
| ![improvement] | The former market open/close (exploit prevention) toggle is now called "Maintenance mode" in the GUI, lang files and docs, with a tooltip explaining it |
| ![bugfix] | Maintenance (closed) state is now saved and survives a server restart, as does an active `/stockmarket open`/`close` override. Worlds last saved with a build before 2.2.0 contain no saved state, so markets closed there come back open once and must be closed again after updating. `/stockmarket close` is a trading-hours override that ends at the next scheduled open/close; to keep a market closed permanently, use maintenance mode |
| ![bugfix] | Enabling maintenance through the market settings now cancels player orders, the same as the checkbox |

## Villager Trading

| Tag | Change |
|---:|---|
| ![improvement] | Villager trade data is now stored in the StockMarket data folder (`data/StockMarket/villager_trades.nbt`) instead of vanilla world storage, on master and slave servers; existing worlds are migrated automatically on server start |
| ![improvement] | Slave servers now also save their villager trade data on the autosave interval instead of only at server stop, so a crash loses at most one interval of villager trades |
| ![feature] | <details><summary>New villager trading option "Replace emeralds for unlisted items"</summary>Emerald trades for items that have no market are converted to money at the emerald market price (emerald count x emerald price, with the buy/sell margins applied). Requires an emerald market, otherwise these trades stay emerald-based. Off by default, toggled in the Mod Settings</details> |

## Administration

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Permission nodes for all admin commands, compatible with LuckPerms</summary>`stockmarket.admin.command.op`, `.manage`, `.preset`, `.news`, `.backup`, `.market`, `.exportrecipes`, `.devtest` and `stockmarket.admin.notify` can be granted or denied per player or group through fabric-permissions-api (Fabric/Quilt) or the NeoForge PermissionAPI. Without a permission mod, each node falls back to operator level 2 as before. See the [admin setup guide](../documentation/user-guide/admin-setup.md#permissions-luckperms)</details> |
| ![feature] | <details><summary>New optional setting "Sync admin flag with LuckPerms" (off by default)</summary>With LuckPerms installed, `/stockmarket op` and `/stockmarket deop` also grant or remove the `stockmarket.admin` permission, and granting or removing that permission in LuckPerms immediately turns StockMarket admin mode on or off. A player who gets `stockmarket.admin` through a LuckPerms group stays an admin after `/stockmarket deop`, and the command says so. Existing StockMarket admins are copied to LuckPerms once when the setting is first turned on. Untrusted slave servers never change admin mode. See the [admin setup guide](../documentation/user-guide/admin-setup.md#syncing-stockmarket-admin-mode-with-luckperms)</details> |

## Bug Fixes

| Tag | Change |
|---:|---|
| ![bugfix] | Server tick handlers were not removed on server stop and stacked up after switching singleplayer worlds; the same applied to the BankSystem event listeners (villager trade broadcast, trust sync, ItemID merge) |
| ![bugfix] | JEI integration was never loaded on Fabric because the mod did not register its JEI plugin entrypoint; the plugin also used the BankSystem plugin id instead of its own |
| ![bugfix] | Stopping the server closed the price/order database while queued writes (such as the final price candle save) were still pending, which could lose them; the database now finishes all queued writes first, and writes arriving after shutdown are rejected with an error log instead of failing silently |
| ![bugfix] | An order rejected on a market under maintenance was reported as created |
| ![bugfix] | Moving an order on the chart of a closed market could lose the order; it is now refused |
| ![bugfix] | TargetPriceBot no longer makes a price jump after a long market closure (PID time step clamped) |
| ![bugfix] | Trade screen (pair mode) and display block chart leaked market price-stream subscriptions |
| ![bugfix] | The display block chart now loads its price history itself; all timeframes work without opening the trading block first |
| ![bugfix] | The trading screen history lists (Market Trades, My History) keep their scroll position while refreshing |
| ![bugfix] | Virtual orderbook: a fast price jump no longer leaves the previous sell volume mirrored as buy volume below the new price |
| ![bugfix] | Item-for-item (inter-market) orders could lose items or sell items that were not locked for the order when the counterparty could not absorb the full amount |
| ![bugfix] | Item-for-item orders with a money buffer sold more of the offered item than needed |
| ![bugfix] | Market orders that can only be partly filled (very large orders or a thin orderbook) now tell the player how much was filled; the rest is cancelled and refunded |
| ![bugfix] | Candle trade volume no longer drops small trades after a very large one |
| ![bugfix] | Target Price Bot no longer overshoots and keeps selling below the target after a long period far away from it |
| ![bugfix] | Target Price Bot orders are capped at the market's max order size times the bot's "Max Order Size Factor" (default 10×), so a large market order can no longer jump the price straight into a far-away player sell order (trading exploit); the virtual order book now re-centers while a bot order walks the price. Markets with an unlimited max order size (0) keep a working, uncapped bot |
| ![bugfix] | A large order whose price walk hits the step limit no longer jumps straight to a far-away player order (trading exploit); markets without virtual liquidity still fill far orders normally |
| ![hardening] | Overflow safety for extremely large balances and order volumes |
| ![hardening] | The display block price chart is registered in the ModUtilities GUI element registry, so a display GUI rebuilt on the client from a server structure update keeps its chart instead of dropping it |
