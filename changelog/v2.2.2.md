## Plugins

| Tag | Change |
|---:|---|
| ![bugfix] | Target Price Bot: markets with very low prices (a few cents) no longer stay stuck after a news reversal. The bot only moved the price when its target was at least a whole price step (0.01) away, which at 0.01 means double the price, so a target of 0.0197 left the price at 0.01 for good. The bot now moves the price to the price step closest to its target, so such a market follows its target price again. It moves the price back against its own last move only when the target is a whole step away or has really turned (moved half a step back from its highest or lowest point since that move), so a target wobbling halfway between two steps doesn't make the price jump back and forth |

## Administration

| Tag | Change |
|---:|---|
| ![bugfix] | Web interface: enchanted books, potions and other items of the same kind all had the same name ("Enchanted Book", "Potion of Swiftness"), so their markets could not be told apart. Names now include the enchantments or potion effects with level and duration ("Enchanted Book (Sharpness V)", "Potion of Swiftness (Speed 08:00)"), and markets whose names are still the same get their market number ("Paper #12"). The Discord feed uses the same names |
| ![bugfix] | Web interface: most items showed only their initials instead of their icon. Icons are now found through the item models, so stairs, slabs, logs, blocks with different sides and mod items with textures in sub-folders show their real texture. A dedicated server has no Minecraft textures of its own, so vanilla items there need the new "Download item textures" setting, or a Minecraft client jar or resource pack copied into `config/StockMarket/web/` (read when the web interface starts). Items of the same kind still share one icon (no enchantment glint, no potion colour) |
| ![feature] | <details><summary>New setting "Download item textures" for the web interface (off by default)</summary>With it on, the master server downloads the Minecraft client of the running version (about 27 MB for 1.21.1) once from Mojang's servers into `config/StockMarket/web/`, checks it against the checksum Mojang publishes, and shows the vanilla item icons right away, without a restart. Only item textures are served from it, nothing else. A failed download is logged and tried again at the next server start or settings change; until then the icons keep their initials. Singleplayer needs no download, it uses the game's own textures. The setting is under Integrations → Web interface in the Mod Settings. See the [admin setup guide](https://kroia.github.io/BanksystemStockmarketDoku/admin/web-interface/)</details> |
| ![bugfix] | Web interface: after you dragged or zoomed the chart's price axis, switching to another market or timeframe kept the old price range, so the new candles could be outside the chart. The chart now recenters on a market's own price range and remembers each market's zoom (and each pair's) in your browser: a market you come back to shows the view you left it with, a new market or timeframe fits its candles |

## News Event System

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Permanent news no longer stacks without limit: each permanent event has a counterpart that slowly reverts it, and markets from older worlds recover</summary>A permanent news event (one that moves a market's default price for good, such as an amethyst geode discovery) could fire again and again, and every firing moved the price further, until some markets sat at the lowest possible price or far above their normal price. Now a permanent event fires only once until it has been reverted. Its counterpart event can fire 3 to 21 days later and moves the price back over 1 to 3 days. If the permanent event fired several times, the counterpart fires as many times, 1 to 3 days apart, each time a step closer to the market's normal price (its preset price) and exactly back to it on the last one; only then can the permanent event fire again. Worlds from older versions count the past firings in their news history once when they load, at most 10 per event (an event that fired more often reverts in larger steps, so it takes no longer than one that fired 10 times), so their markets start recovering. 9 new counterpart events ship with the mod, and the existing gold standard and luxury tax repeal events became the counterparts of the gold standard and the luxury tax. Custom events name the event they revert with `undoes` and can set the delays with `undoDelaySeconds` and `undoRepeatDelaySeconds`; a custom permanent event without a counterpart fires only once (the server log warns about it). `/stockmarket news info`, the news event details and the admin event list show how many reversals are pending and when the next one can happen</details> |
| ![bugfix] | Existing servers and worlds kept their old default news pictures after an update, so redrawn pictures never showed up there. A default picture in `config/StockMarket/news/pictures/` that is still exactly a picture the mod shipped before is now replaced by the current one when the news events load; pictures an admin replaced or edited are kept |

## API

| Tag | Change |
|---:|---|
| ![bugfix] | Market access API: on the master, the asynchronous market and market manager calls ran on whichever thread called them, so an addon calling them from its own thread could change a market while the server was updating it and crash the server. These calls now always run on the server thread. Called from the server thread, the result is still ready at once; called from another thread, the future completes once the server has run the call |
