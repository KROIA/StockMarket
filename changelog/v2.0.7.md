# v2.0.7 — 2026-07-29

Paginated candlestick chart history. Charts now load only what you view and page in older data on demand, so the last week is no longer the ceiling — you can scroll all the way back to the beginning of the market. Also: new op-only `/stockmarket backup` subcommands to quiesce the SQLite database for external filesystem backups.

## Performance

| Tag | Change |
|---:|---|
| ![improvement] | <details><summary>Chart history loads lazily instead of flooding on world join</summary><br>Previously every market fired six candle-delta requests when the world loaded — 750 SQL round-trips for a 125-market world. Now nothing is fetched until you actually open a chart, and each candle-delta is fetched exactly once per market for the session.</details> |
| ![bugfix] | <details><summary>SQLite "cannot commit — no transaction is active" spam eliminated on read paths</summary><br>Read queries in `MarketPriceManager` and `OrderRecordManager` were calling `commitTransaction()` on bare SELECTs. SQLite doesn't open an implicit transaction for reads under `autoCommit=false`, so every query logged an error. Removed the commit calls on read paths; write paths still commit.</details> |

## Trading Terminal

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Candlestick chart pagination — scroll back to the start of the market</summary><br>The chart used to be capped at ~5 days of client-side data, so 1-day candles showed maybe five bars. Now the server sends an initial window at the delta you're viewing (default 512 candles, admin-tunable), and older data streams in whenever you pan or scroll toward the left edge. A "Loading older data..." indicator marks in-flight fetches. Immutable historical candles are cached per-delta on the client, so re-visiting a range costs zero network traffic. When you reach the very first candle of the market, the chart clamps normally.</details> |
| ![feature] | ![improvement] Cross-rate charts paginate the same way — both underlying markets fetch in parallel and the cross-rate is recomputed. |
| ![improvement] | <details><summary>Auto-fit vertical view the first time you switch to an unused candle timeframe</summary><br>Switching to a candle delta whose data hasn't been loaded yet used to leave the chart at an arbitrary vertical range until you pressed spacebar. Now the vertical range fits the visible candles automatically the first time data lands for that delta — exactly like a spacebar press. Subsequent switches to already-viewed deltas keep whatever view you had. Same-timeframe reclicks are a no-op.</details> |
| ![bugfix] | <details><summary>Old-save gap now fills correctly even at short candle deltas</summary><br>Loading a world days after last save, on 1-minute candles the initial ~8.5 h window fell entirely inside the gap so the chart came up empty and pagination couldn't be triggered. The server now reports its oldest available timestamp with every response, and the client auto-bootstraps a follow-up fetch aimed at where the real data lives. Artificial gap-fill candles then span the range from the newest real candle to now. |</details> |
| ![bugfix] | Panning to older candles no longer wipes the previously-visible newer candles — the chart now re-renders from the full merged cache after each pagination response, not from only the latest chunk. |

## Administration

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>`/stockmarket backup pause|resume|status` — op-only DB quiesce for filesystem backups (#79)</summary><br>External backup scripts (`tar`, `rsync`) that snapshot the world directory used to risk capturing `stockdata.db` and `stockdata.db-journal` mid-transaction, producing torn restores. `/stockmarket backup pause` submits a "commit + park" job onto the single-thread db-worker executor and logs `[StockMarket] db-worker paused for backup` once the job actually runs (i.e. all prior writes have drained). The backup script watches for that line before starting its archive. `/stockmarket backup resume` releases the pause. `/stockmarket backup status` reports paused/running + elapsed seconds. Op permission (level 2); master-server only.<br><br>**Safety:** 120 s auto-resume if the operator forgets `resume`, with a WARN log line.<br>**No data loss during pause:** writes submitted while paused (trades, order records, per-interval candle rotations) are queued FIFO on the db-worker executor and drain on resume — including in-memory candle buffers, which now rotate on tick regardless of whether a prior SQL save is still parked.</details> |
